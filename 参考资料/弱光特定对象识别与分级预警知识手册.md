# 弱光特定对象识别与分级预警知识手册

**版本**：0.2

**整理日期**：2026-08-22
**适用项目**：基于多模态视觉与边缘计算的弱光特定对象识别及分级预警系统

> 本手册是工程学习和原型设计资料，不是法律意见，也不证明任何模型适合生产或特定业务。人脸识别只应在有明确授权、必要性和人工复核的场景中使用。检索来源和访问日期列在文末，模型、论文和法规可能更新，正式发布前应再次核验。

## 1. 先建立正确的问题模型

### 1.1 从“认人”变成“确认事件”

一个可审计的预警系统至少要回答五个不同问题：

1. 画面里有没有人脸？
2. 当前画面质量是否足以进行判断？
3. 这个人是否与某个已授权模板相似？
4. 这个目标是否连续出现、正在进入或停留在指定区域？
5. 事件是否达到需要提醒的等级？

这些问题不能由一个分数或一个神经网络一次性代替。推荐链路是：

```text
采集 -> 设备健康 -> 检测 -> 质量门控 -> 对齐/特征 -> 开放集匹配
     -> 多帧确认 -> 轨迹与区域 -> 事件分级 -> 本地记录/通知
```

身份结论和事件风险结论必须分离。身份不确定时，系统应诚实输出 `uncertain` 或 `unusable`，而不是选择一个看似最接近的对象。

### 1.2 术语速查

| 术语 | 含义 | 在本项目中的用法 |
|---|---|---|
| 检测（detection） | 找到脸的位置和关键点 | YuNet 输出框、五点关键点和分数 |
| 验证（1:1） | 比较两张脸是否为同一人 | 注册模板与当前脸的相似度 |
| 识别（1:N） | 在 N 个模板对象中找候选 | 当前项目的开放集匹配 |
| 开放集 | 现场可能出现模板库之外的人 | 必须允许 `unknown` |
| 质量门控 | 识别前筛除不可用输入 | 暗、亮、模糊、过小、姿态异常等 |
| FMR | False Match Rate，错误把异人匹配为同人的比例 | 约束误认风险 |
| FNMR | False Non-Match Rate，同人未匹配成功的比例 | 衡量漏认 |
| 轨迹（track） | 跨帧关联的同一视觉目标 | 用于稳定身份和计算停留时间 |
| 事件 | 一段有开始、状态变化和结束的行为 | 进入、停留、离开，而非每帧告警 |

## 2. 弱光成像基础

### 2.1 为什么“把画面变亮”不等于“识别变好”

低照度下，传感器通常同时遇到光子噪声、读出噪声、运动模糊、色偏和动态范围不足。提高增益可以让平均亮度上升，却也会放大噪声；延长曝光可能带来拖影；逆光会让脸部区域仍然欠曝。增强算法还可能改变局部纹理，使人眼观感变好但特征匹配变差。

因此质量模块至少要记录：

- 人脸框大小或两眼间距；
- 人脸裁剪区域平均亮度和过曝比例；
- Laplacian 方差或其他相对清晰度；
- 关键点推断出的水平/垂直姿态；
- 检测器分数、帧时间和摄像头曝光参数（能读取时）。

本项目当前的 `FaceQualityEvaluator` 已覆盖人脸尺寸、平均亮度、Laplacian 清晰度和简化姿态，是很好的第一版门控，但阈值不能被当作通用标准。应按摄像头、安装距离和镜头视场重新标定。

### 2.2 成像优先级

建议按以下顺序排查弱光问题：

1. 调整摄像头位置、补光角度、曝光上限和白平衡。
2. 使用固定、可记录的快门/增益组合，避免相邻帧亮度大幅波动。
3. 增加轻量的白平衡、降噪或 gamma/CLAHE 分支，并用识别指标验证。
4. 有完全黑暗需求时，评估近红外相机和红外补光；不要期待普通 RGB 摄像头在无光环境中凭算法恢复不存在的信息。
5. 最后才考虑更重的低光增强模型或模型再训练。

### 2.3 低光数据和增强研究

《Getting to Know Low-light Images with The Exclusively Dark Dataset》指出，常见目标检测基准中的低光图像比例很低，并提出专门的 ExDark 数据集。这说明在普通数据集上的准确率不能直接代表走廊、宿舍或夜间摄像头表现。

Zero-DCE 是一种零参考低光增强方法，使用图像特定的曲线估计，不依赖成对参考图像。它适合做对照实验，但论文中的增强目标不是本项目的身份识别目标。实验应比较“增强前后下游检测/识别/延迟”，而不是只展示更亮的截图。

推荐实验分支：

```text
同一原始帧
  |- 原图 -> 检测 -> 质量 -> 识别
  |- 轻量预处理 -> 检测 -> 质量 -> 识别
  `- 低光增强模型 -> 检测 -> 质量 -> 识别
```

所有分支使用相同阈值标定协议和独立测试集，避免挑选最漂亮的结果。

## 3. YuNet 检测与 SFace 特征

### 3.1 YuNet 的能力边界

OpenCV 官方教程使用 `FaceDetectorYN` 做检测、`FaceRecognizerSF` 做识别；OpenCV Zoo 的 YuNet 模型卡报告其在 WIDER Face 验证集上的 AP，并说明由于训练方案，适合检测约 10x10 到 300x300 像素范围内的人脸。这个范围是模型卡和基准条件下的参考，不是对本项目摄像头距离的保证。

对当前项目的具体启示：

- 安装时要先反推目标脸部像素尺寸，再决定分辨率、镜头和距离。
- 远处小脸、严重侧脸、遮挡和强噪声应单独统计，不应与正面近景平均。
- `2023mar` 模型是固定输入形状版本；当前代码会按帧调用 `setInputSize`，升级 OpenCV/推理引擎时要做回归测试。
- 检测器分数只是候选置信度，不是身份相似度，也不是事件风险分数。

### 3.2 SFace 的使用方式

OpenCV Zoo 的 SFace 模型卡说明模型基于 MobileFaceNet 和 SFace 损失，并支持五点关键点对齐。当前实现的流程与官方示例一致：

```text
YuNet 五点关键点
-> FaceRecognizerSF.alignCrop
-> feature
-> L2 归一化
-> 余弦相似度（归一化向量点积）
```

OpenCV 教程给出了 LFW、CALFW 等公开基准的示例准确率和余弦阈值（例如教程代码中的 `0.363`）。这些数字只描述特定模型、数据集和评测协议，不能直接作为本地摄像头阈值。当前项目必须用自己的授权采集、未登记对象和弱光测试集重新选择阈值。

### 3.3 模板库设计

当前 [TemplateStore](../src/lowlight_alert/template_store.py) 使用压缩 NPZ 和 JSON manifest，优点是简单、原子替换、便于原型测试；缺点是默认没有加密、密钥管理或并发写入控制。

早期阶段的控制：

- 每个对象使用随机/非敏感 `subject_id`，显示名与稳定身份信息分离。
- 注册前做质量门控，并拒绝近重复模板。
- 记录模型版本、模板生成时间、质量指标和同意记录 ID，但不保存原始帧。
- 读取模板时校验 schema、维度、有限值和对象 ID。
- 运行目录和访问权限只对必要用户开放；演示结束后执行删除。

后续要对外部署时，应增加加密存储、密钥轮换、访问审计和模板备份删除策略；加密不能替代访问控制。

## 4. 质量门控和阈值标定

### 4.1 质量不是“附加分”，而是拒答机制

NIST FATE Quality 评测把质量算法与识别失败联系起来，并讨论相对模糊度（按眼间距归一化）、姿态等质量因素。核心思想是：质量模块可以优先拒绝最不可能可靠识别的输入，从而减少错误匹配；它不能把不可见的信息变出来。

建议输出两层结果：

```text
quality_state = pass | reject
quality_issues = [too_dark, blurry, small, pose, invalid_crop, ...]
```

不要把 `reject` 直接转换为 `unknown`。前者表示“证据不足”，后者表示“输入足够但与授权库不匹配”。这两个状态对事件策略和人工复核不同。

### 4.2 阈值标定流程

1. **定义任务**：本项目是开放集 1:N 识别，不能只测闭集分类准确率。
2. **划分数据**：按采集会话划分开发集和测试集；同一连续视频不能跨集合。
3. **采集分数**：记录同人（genuine）和异人（impostor）相似度分布，以及质量指标。
4. **选择阈值**：先确定可接受 FMR，再在开发集选择满足约束的阈值；必要时使用接受阈值和拒绝阈值之间的灰区。
5. **冻结并验证**：测试集只使用一次，报告 TAR/FMR/FNMR、质量分层和置信区间。
6. **按条件复测**：普通光、昏暗、逆光、姿态、距离和遮挡分别报告，不能只给总平均。

NIST FRTE 1:1 页面把 FNMR 定义为低于阈值的同人比较比例，把 FMR 定义为达到或超过阈值的异人比较比例。项目报告应沿用这类术语，并明确阈值对应的 FMR，而不是只写“准确率 95%”。

### 4.3 一个可复现的分数表

```text
model_version, threshold_version, sample_id, subject_pair,
genuine_or_impostor, similarity, quality_passed, light_condition,
pose, occlusion, decision
```

阈值表至少记录：阈值值、相似度类型（cosine/L2）、开发集版本、目标 FMR、测试集结果、批准人和生效日期。

### 4.4 公平性和样本限制

NIST 的人口统计评测显示，FMR/FNMR 可能随性别、年龄和出生地区等分组而变化，且质量和数据代表性会影响结果。两名授权对象的课堂原型不能得出人口统计公平性结论；正确做法是声明样本不足，不做泛化宣传，也不收集与用途无关的敏感属性。

## 5. 多帧融合、跟踪和区域状态机

### 5.1 检测、跟踪和识别的分工

- 检测回答“这一帧哪里有脸”。
- 跟踪回答“相邻帧是不是同一个视觉目标”。
- 识别回答“这个稳定目标是否像某个授权模板”。
- 事件状态机回答“是否进入、停留或离开区域”。

不要每帧重新注册或每帧直接发通知。当前 MVP 先用框 IoU 和短时丢失容忍；真实回放后再决定是否增加中心点门控、时间门控或 ByteTrack 等成熟关联方法。ByteTrack 论文的关键思路是不要简单丢弃低分检测框，而是利用其中仍可能属于真实目标的框减少轨迹碎片；使用前仍需在本项目数据上验证。

### 5.2 推荐轨迹生命周期

```text
无 -> tentative -> confirmed -> lost -> ended
                 |             |
                 +-------------+
                   短时重新关联
```

- `tentative`：连续命中不足，不能产生身份告警。
- `confirmed`：连续命中、质量合格且身份分数稳定。
- `lost`：暂时遮挡或丢帧，保留有限时间。
- `ended`：超时离开，关闭事件并计算停留时长。

身份稳定器应保存最近窗口的分数、质量和候选对象；当最佳对象变化但差值很小，输出 `uncertain`，而不是立刻切换。

### 5.3 区域与风险分级

用摄像头坐标系中的多边形区域表示“监测区”和“警戒区”。风险分级应由事件证据组合：

```text
event_score = zone_weight
            + dwell_weight
            + approach_weight
            + time_window_weight
            + sensor_agreement_weight
```

身份不是危险分数。建议原型只使用“记录/注意/高优先级”三态，并为每级定义进入条件、升级条件、降级条件、冷却时间和人工复核动作。

## 6. 事件日志和通知设计

### 6.1 本地事件记录

早期可使用 JSONL 或 SQLite；每行/每条记录是完整事件，而非每帧状态。建议字段：

```json
{
  "event_id": "evt-20260808-000001",
  "camera_id": "cam-01",
  "event_type": "zone_enter",
  "zone": "door-east",
  "identity_state": "registered",
  "subject_id": "person-a",
  "severity": 1,
  "confidence": 0.91,
  "first_seen_at": "2026-08-08T18:00:00+08:00",
  "observed_at": "2026-08-08T18:00:01+08:00",
  "duration_seconds": 1.2,
  "evidence": ["quality_pass", "multi_frame_confirmed"],
  "threshold_version": "dev-03",
  "delivery_state": "local_only"
}
```

时间戳使用带时区的 ISO 8601；系统时钟异常应记录设备状态。事件 ID 要稳定，便于重试幂等和审计。

### 6.2 MQTT/HTTPS 的后续原则

MQTT 5.0 标准定义 QoS、会话过期、消息过期、Will Message、原因码和 TLS 相关机制。Eclipse Paho Python 客户端支持 MQTT 5.0/3.1.1/3.1，并提醒客户端对象重建时本地会话状态的持久化限制。

推荐做法：

- 事件确认后先写本地 outbox，再异步发布；不要在摄像头循环中同步等待网络。
- 告警通常从 QoS 1 开始，消费者按 `event_id` 去重；QoS 2 不能替代应用层幂等。
- 使用 TLS、服务端证书校验、独立账号和最小 topic ACL；不把 Broker 暴露到公网。
- 对告警设置消息过期时间，避免几小时后的过期警报被当成当前事件。
- 默认不使用 retained 告警消息；设备在线状态可使用受控的状态 topic 和遗嘱消息。
- 断网时本地继续识别，恢复后按时间和优先级补发，并记录过期/丢弃原因。

HTTPS 方案同样需要 TLS、认证、超时、指数退避、幂等键和本地 outbox。手机推送服务只接收已确认事件，不接收原始连续视频。

## 7. 边缘推理和性能

### 7.1 先建立 CPU 基线

当前项目已经以 OpenCV DNN + ONNX Runtime CPU 为基础。边缘部署前固定以下变量：模型文件哈希、输入分辨率、线程数、摄像头 FPS、批大小（通常为 1）和执行提供者。

记录：

- 冷启动和模型加载时间；
- 检测、质量、特征、融合各阶段耗时；
- 端到端 p50/p95/p99 延迟；
- 实际 FPS、CPU/GPU 利用率、内存和温度；
- 摄像头读帧失败、队列长度和丢帧数。

ONNX Runtime 的性能文档建议结合执行提供者、图优化和 profiling 工具测量；不要用单次 wall-clock 读数推断长期性能。

### 7.2 量化和模型替换

ONNX Runtime 文档区分动态量化和静态量化：静态量化需要校准数据，动态量化在运行时计算部分参数。量化可能降低精度，也可能因硬件指令不匹配而不增反降。

实施顺序：

1. 保存 FP32 CPU 基线和测试结果。
2. 用代表性、非敏感校准帧尝试量化。
3. 对同一测试集复测检测、识别和事件指标。
4. 只有性能收益超过精度和维护成本时才保留量化模型。

### 7.3 设备健康和降级

设备状态本身也是事件输入：摄像头断开、帧率低于下限、镜头被遮挡、磁盘接近满、模型加载失败和网络不可用都应有状态码。降级时宁可输出“系统不可确认”，也不要继续生成看似正常的身份告警。

## 8. 隐私、安全和合规基线

### 8.1 适用规则的基本事实

中国人大公开的《中华人民共和国个人信息保护法》第二十八条将生物识别列为敏感个人信息，第二十九条要求处理敏感个人信息取得个人单独同意，第三十条要求告知处理必要性及对个人权益的影响；第五十一条要求采取防止未授权访问、泄露、篡改和丢失的措施，第五十五条规定特定处理活动应事前进行个人信息保护影响评估并记录。

中央网信办公布的《人脸识别技术应用安全管理办法》页面显示，该办法自 2025-06-01 起施行。其内容涉及告知处理目的和保存期限、单独同意、最小必要保存、设备内存储/网络传输限制以及事前影响评估等要求。项目实际是否适用、由谁承担处理者责任和是否需要额外备案，应由学校/单位的合规负责人或专业法律人员确认；手册不替代审查。

### 8.2 原型必须做到的最小控制

- 明确用途和监测区域，避免把“做实验”扩大为无关人员监控。
- 只采集明确同意的对象；未登记人员默认只产生不可识别的统计/事件状态。
- 提供撤回和删除流程，并记录模板、抓拍、日志的最短保存期限。
- 原始视频默认不落盘；必要抓拍短期、加密、严格访问控制并自动删除。
- 模板和密钥分开保存；限制能够读取模板的账户和进程，记录访问审计。
- 演示数据去标识化；不把 `data/`、`captures/`、`logs/`、密钥或模型大文件提交 Git。
- 识别不确定时转人工核查；系统不能自动对个人采取惩罚性措施。

OWASP Cryptographic Storage Cheat Sheet 建议使用现代、经认证的加密模式，保护密钥并将密钥与数据分离。对本项目而言，这意味着“把 NPZ 压缩”不能被当作加密；后续加密设计要单独解决密钥生命周期和访问权限。

### 8.3 人脸反欺骗

照片、手机屏幕、视频回放和面具可能骗过普通人脸匹配。当前 MVP 明确不覆盖活体检测/Presentation Attack Detection（PAD），演示时应写出这一限制；如进入真实门禁或高风险场景，必须把 PAD、人工复核和备用凭证作为独立安全需求，而不是暗中提高相似度阈值。

## 9. 常见失败模式与处理策略

| 现象 | 不应做的事 | 推荐处理 |
|---|---|---|
| 人脸过暗/过小 | 强行给出身份 | `unusable`，提示调整成像或补光 |
| 相似度在阈值附近 | 选择最高分并告警 | 双阈值灰区，等待更多帧或人工复核 |
| 单帧误检 | 每帧发通知 | 轨迹确认、窗口投票、冷却 |
| 多人同时出现 | 任意绑定到目标对象 | 分别建轨迹；身份不确定时不升级 |
| 短时遮挡 | 立即结束并重建事件 | `lost` 状态保留有限时间 |
| 摄像头被遮挡 | 继续输出“无人” | 设备异常事件，停止身份告警 |
| 网络断开 | 丢弃或阻塞采集循环 | 本地 outbox、过期策略、恢复补发 |
| 模型更新 | 直接沿用旧阈值 | 模型/阈值版本绑定并重新标定 |
| 量化后更快 | 只看 FPS | 同集复测 FMR/FNMR 和质量分层 |

## 13. 一句话结论

本项目的技术主线应是“质量感知的开放集识别 + 多帧事件状态机 + 可审计的本地分级预警”。只有在这条主线用数据证明可靠之后，才把 NIR、雷达、MQTT、GPU 和手机端作为可验证的扩展，而不是把功能数量当作项目价值。
