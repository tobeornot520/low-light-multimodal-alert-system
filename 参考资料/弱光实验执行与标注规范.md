# 弱光实验执行与标注规范

**版本**：Draft 0.3
**日期**：2026-08-26
**适用范围**：T11 前置准备及后续真实弱光验收。

## 1. 阶段边界

当前先完成 **E0：离线实验与审计就绪**：固定数据协议、按视频媒体时间回放、导出逐帧遥测和机器可读报告，并用非敏感合成视频验证工程链路。

采集到明确授权的真人数据后，才能进入 **E1：实采弱光验收**，报告检测、开放集识别、区域事件和系统性能指标。E0 通过不代表 T07 阈值标定、T11、Gate A～D 或生产验收完成。

## 2. 一次只改变一个主要变量

基础实验先固定摄像头、位置、区域、分辨率、FPS、距离、姿态、运动脚本、模型和阈值，仅改变光照：

| 条件 ID | 场景定义 | 必须包含 | 预期失效行为 |
|---|---|---|---|
| `normal` | 正常室内照明 | registered、unknown、empty | 建立基线 |
| `dim` | 明显昏暗但肉眼可辨 | 同一对象和运动脚本 | 质量拒绝率可能上升 |
| `backlight` | 人脸相对背景欠曝 | 同一对象和运动脚本 | 不强行输出身份 |
| `near_black` | RGB 信息接近不可用 | registered、unknown、empty | 应可靠拒答或报告设备边界 |

完成基础组后，再分别增加遮挡、快速经过和多人。不要在同一轮同时改变光照、距离、相机、区域和运动方式。

## 3. 本地目录

真实媒体、标注、授权和删除记录不得进入 Git。建议每次实验独立目录：

```text
data/experiments/<experiment_id>/
  manifest.yaml
  sources/<run_id>.mp4
  observations.csv
  event_truth.csv

logs/replays/<run_id>/
  events.jsonl
  frames.csv
  report.json
```

从 [experiment.example.yaml](../config/experiment.example.yaml) 建立本地 `manifest.yaml`。对象只使用 `person-a`、`unknown-a` 等项目内假名；真实姓名、联系方式和同意文件保存在仓库外的受控位置。

需要 RGB、NIR、热成像或 ToF 的联合实验时，从 [multimodal-manifest.example.yaml](../config/multimodal-manifest.example.yaml) 建立 manifest。每个模态都必须记录自己的文件、帧率、时间偏移、视场或标定记录；未同步的多个视频不能被标为“融合实验”。采集前可执行：

```powershell
.\.venv311\Scripts\python.exe run.py validate-manifest data\experiments\<experiment_id>\manifest.yaml
```

## 4. 采集前冻结项

每个 run 开始前记录：

- `experiment_id`、`run_id`、`dev/test` 用途和输入策略。
- 原始视频 SHA-256、采集会话、FPS、时长和镜像策略。
- 摄像头型号、镜头、安装位置、分辨率、曝光、增益和 IR 状态。
- 光照类别、照度值、测量工具和测量位置。手机 App 只能标注为粗略测量。
- 参与的模态（RGB、NIR、热成像、ToF），各自的时间基准、帧率、视场和相对安装位置。RGB 与 NIR 可以共享身份特征验证；热成像首先用于有人/区域存在证据，不应在没有独立验证前承担身份结论。
- 登记会话、测试会话和授权记录 ID；登记与测试必须按会话隔离。
- Git 版本、配置和模型哈希、阈值版本。
- 原始视频、模板、日志和标注的最短保存期限及删除记录 ID。

## 5. 回放

先在 `config/default.yaml` 配置区域，再执行无窗口回放：

```powershell
.\.venv311\Scripts\python.exe run.py --config config/default.yaml replay data\experiments\exp-lowlight-001\sources\run-normal-001.mp4 --condition normal --experiment-id exp-lowlight-001-run-normal-001
```

回放默认使用视频 FPS 和 `frame_index / fps` 作为源时间，逐帧 CSV 字段名为 `source_time_s`，不能用处理速度代替媒体时间。FPS 元数据不可用时必须显式指定 `--source-fps`。镜像策略必须与区域坐标定义一致；使用 `--no-mirror` 时要在 manifest 中记录。视频读帧结束时使用 `frames_processed / fps` 作为 EOF 边界；`--max-frames` 是人为截断，不代表源文件完整。

每次 run 使用独立输出目录。回放会先写临时产物，完成解码、事件日志一致性和报告校验后再发布；失败不会留下可被误读的完整报告。`report.json` 中的检测数、质量拒绝、身份状态和事件数是系统观察量，不是准确率；没有人工真值时不得据此声称召回率或误报率。EOF/`machine_flush` 收尾事件应与人工 `event_truth.csv` 的真实离开分开统计。

## 6. 人工标注

### 6.1 `observations.csv`

一行表示一个匹配人脸、漏检真值或无真值预测。第一版至少包含：

```text
run_id,frame_index,source_time_s,gt_face_id,gt_subject_id,
gt_identity_class,gt_usable,gt_bbox_x,gt_bbox_y,gt_bbox_w,gt_bbox_h,
pred_detection_id,pred_bbox_x,pred_bbox_y,pred_bbox_w,pred_bbox_h,
iou,quality_passed,quality_issues,identity_state,pred_subject_id,
similarity,runner_up_similarity,track_id,track_confirmed
```

`gt_identity_class` 只使用 `registered`、`unknown` 或 `none`。漏检行的预测字段为空，无真值误检行的 GT 字段为空。相邻帧不是独立实验样本，汇总时优先按 trial 或采集会话统计。

### 6.2 `event_truth.csv`

人工标注进入、停留和离开的源视频时间窗：

```text
truth_event_id,run_id,trial_id,zone,event_type,gt_subject_id,
gt_identity_class,expected_time_s,tolerance_before_s,tolerance_after_s,
expected_severity
```

系统事件必须按 `run + zone + event_type + subject` 和时间窗进行一对一匹配。一个真值匹配后的额外同类事件计为重复事件；视频 EOF 产生的 `machine_flush` 需要单列，不得冒充真实离开。

## 7. 指标口径

有真值后分别报告：

- 检测：TP、FP、FN、precision、recall、FP/分钟，IoU 阈值必须写入协议。
- 质量：可用样本通过率、不可用样本拒绝率、各拒绝原因和端到端不可用率。
- 识别：TAR/FMR/FNMR，同时单列正确识别率、错认率、unknown 错误接受率和 `uncertain` 比例。
- 事件：precision、recall、F1、重复数、延迟 p50/p95、离开时长误差和等级准确率。
- 系统：有效 FPS、逐帧处理时间 p50/p95、读帧/解码失败；CPU、内存和温度只有采样后才能报告。

所有比例同时保存分子、分母和值；分母为 0 时写 `null`。pairwise FMR 不能替代运行时 unknown 被错误识别为登记对象的概率。

多模态运行还应单列：每个模态可用率、模态冲突率、在 RGB 质量拒绝时 NIR/热成像的降级决策，以及模态缺失情况下的事件指标。融合逻辑不得把“检测到人”误写为“已确认身份”。

## 8. 必须人工确认的内容

- 同意范围、对象角色、登记/测试会话划分和删除期限。
- 人脸真值框、身份类别、样本是否可用及遮挡/姿态类别。
- 区域越界时间和多人遮挡歧义。
- 光照条件、照度工具/位置和相机曝光设置。
- 失败案例归因、是否需要重采，以及最终删除动作。

亮度、清晰度、模型分数、系统决策、事件、文件哈希和处理耗时应自动记录，不应手抄。

## 9. E0 验收

E0 通过需要：同一视频重复回放得到相同的事件类型和媒体时间；无 GUI 环境可运行；坏文件、坏 FPS、声明帧数不完整、帧尺寸变化和重复目录明确失败；每次 run 产生独立事件日志、逐帧遥测和 JSON 报告；报告记录输入、配置和模型哈希、终止原因、源完整性和输出哈希；合成回放覆盖短时丢帧、超时、EOF、截断和镜像策略。

E0 只能声明“实验协议和回放链路就绪”。没有授权真人数据和目标设备记录时，不报告真实弱光准确率、5 分钟稳定性、目标设备 FPS/p95，也不进入 MQTT、NIR、GPU 或低光增强模型扩展。
