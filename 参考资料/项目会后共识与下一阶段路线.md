# 项目会后共识与下一阶段路线

**更新日期**：2026-08-29

## 1. 项目定位

项目暂定定位为：

> 面向固定、授权场景，利用 RGB/NIR 多模态感知与边缘计算，稳定确认特定人员，对具有明确物理定义的人员行为进行早期识别，并形成可解释的分级预警和结构化事件数据。

“各种情况下稳定识别”在实验和申报中统一改写为：

> 在预先定义的光照、距离、姿态、遮挡、运动和模态可用条件内报告识别性能、工作范围和失效边界；证据不足时输出 `uncertain` 或 `unusable`。

“行为预先识别”统一使用“行为早期识别”表述。它表示在目标行为已经出现部分可观察证据、但尚未完成时进行判断，不表示在缺乏证据时预测某个人的意图或危险性。

## 2. 核心研究主线

### 2.1 复杂条件下的特定人员稳定确认

- 采用多会话、多模板注册，而不是用连续视频相邻帧扩充样本。
- 使用质量门控区分可用输入与不可用输入。
- 在开放集环境中区分 `registered`、`unknown`、`uncertain` 和 `unusable`。
- 使用多帧跟踪和身份融合降低单帧身份抖动。
- 分条件报告正确确认、错误接受、错误拒绝、灰区和首次稳定确认时间。

### 2.2 RGB/NIR 双模融合识别

- RGB 作为正常光和一般弱光的身份基线。
- NIR 作为近黑条件下的人脸纹理补充模态。
- 同协议比较 RGB、NIR 和 RGB/NIR 融合三条路径。
- 第一版优先采用可解释的决策级融合，再根据配对数据决定是否研究分数级、特征级或跨光谱模型。
- 单路失效或两路冲突时保守降级，不能把“检测到人”直接升级为“确认身份”。

### 2.3 特定行为早期识别与预警

第一轮优先选择 2～4 个能够一致标注的行为，例如：

- 持续接近警戒区域；
- 进入指定区域；
- 超时停留；
- 在时间窗内重复进入、离开或折返；
- 在机位和标注条件允许时，研究向指定设备区域伸手或操作。

第一版使用轨迹、区域、方向、速度、持续时间和状态机建立规则基线。只有规则在真实回放中稳定失败、行为定义一致且独立数据充足时，才考虑姿态模型或时序行为模型。

身份和行为保持分离：

```text
身份证据 + 轨迹证据 + 场景证据
                ↓
          特定事件候选
                ↓
      分级预警与必要的人工复核
```

不得使用“识别到某个人，因此此人具有危险性”的逻辑。

### 2.4 结构化事件分析

后续数据分析以结构化事件为主，不以集中保存大量原始人脸视频为目标。建议保留：

```text
时间、区域、匿名对象编号、身份状态、行为类型、
持续时间、预警等级、模态可用性、人工复核结果、
处理延迟、设备状态、失败原因、模型和阈值版本
```

第一版使用 SQLite 或 PostgreSQL 即可。只有事件量、并发和查询压力产生实际需求后，再评估流处理或分布式分析平台。

## 3. 三层系统架构

```text
感知与边缘层
RGB / NIR / 同步 / 检测 / 质量 / 身份 / 跟踪 / 行为事件
                         ↓
可信传输层
结构化事件 / 认证 / 加密 / 幂等 / 缓存 / 重试 / 审计
                         ↓
管理与应用层
事件展示 / 人工复核 / 查询 / 报表 / 权限 / 数据治理
```

三层描述部署位置；检测、识别、跟踪、融合、事件和评测仍保留各自接口，不能因为部署在同一设备就混成一个模块。

## 4. 当前已经具备的基础

当前本地工作区已经具备：

- YuNet 人脸检测；
- 亮度、清晰度、尺寸和姿态质量门控；
- SFace 特征提取、授权模板注册和模板存储；
- 开放集匹配与 `registered / unknown / uncertain` 状态；
- IoU 多帧跟踪、身份投票和短时丢失容忍；
- 区域进入、停留和离开状态机；
- 0～2 级事件、本地 JSONL 日志和画面提示；
- 无窗口视频回放、逐帧遥测和审计报告；
- 数据 manifest 校验和多模态保守融合内核；
- 阈值、开放集和事件级指标计算内核；
- 153 项自动化测试通过，Ruff 静态检查通过。

这些结果证明代码结构和离线工程链路可运行，不证明真人、真实弱光、RGB/NIR 或目标边缘设备性能已经达到要求。

## 5. 当前尚未完成

- 目标摄像头连续运行和异常恢复验收；
- 正式授权、按会话隔离的本地真人数据；
- 接受、拒绝、灰区和质量阈值冻结；
- RGB/NIR 设备接入、标定、同步采集和跨谱验证；
- 特定行为的定义、试验脚本、标注一致性和早期识别指标；
- 从标注数据到完整开放集、行为和事件报告的一键工具；
- 可靠事件传输、管理终端和目标边缘设备性能报告；
- 生产级活体检测、模板加密、权限和撤回删除工具。

## 6. 推荐阶段路线

### M1：RGB 实采基线与 NIR 准备

- 固定场景、设备、距离和区域。
- 建立授权对象与 unknown 的分会话数据。
- 冻结 RGB 身份与基础事件指标。
- 完成 NIR 设备选型、补光、安全资料、同步和标定方案。

### M2：RGB/NIR 双模闭环

- 同步采集 RGB/NIR 数据。
- 完成 RGB、NIR、融合三组对照。
- 报告模态可用率、冲突率、身份指标、延迟和失效降级。

### M3：行为早期识别

- 冻结 2～4 个目标行为的起点、完成条件和容许时间窗。
- 建立跟踪与规则基线。
- 报告行为 precision、recall、F1、误报率、延迟和预警提前量。
- 只有基线失败证据充分时才微调行为模型。

### M4：边缘应用与结构化事件分析

- 完善设备健康、事件存储、可靠传输和人工复核。
- 在目标设备测量 FPS、p50/p95 延迟、资源、温度和稳定性。
- 建立结构化事件查询、统计和版本对比。

### M5：冻结验收与成果整理

- 用独立测试集完成身份、双模、行为、事件和系统报告。
- 形成演示、部署手册、接口说明、数据治理记录和结题材料。
- 根据证据决定热成像、ToF、门磁或更大规模分析是否另行立项。

## 7. 数据规模分级

### 工程试运行

- 2～5 名授权对象；
- 至少 3～5 名 unknown；
- 每名授权对象至少 3 个独立会话；
- 四类光照和基础区域事件。

该规模只用于打通链路和发现问题，不能支持广泛人群泛化结论。

### 正式项目评测

在取得学校要求的审批和书面同意后，根据招募能力争取：

- 10～20 名授权参与者；
- 不少于授权对象数量的 unknown 参与者，最好进一步扩大；
- 每人至少 3 个独立会话；
- 注册、开发和冻结测试按会话隔离；
- 行为以 trial 为统计单位，不把相邻帧当作独立样本。

如果无法达到该规模，应将成果明确定位为受控场景案例研究，不作人口统计公平性或通用识别能力宣称。

4. 参与者招募、审批、同意、保管和删除责任。
5. 五个模块的交付人与接口复核人。
6. M1 截止日期及进入 M2 的验收条件。
